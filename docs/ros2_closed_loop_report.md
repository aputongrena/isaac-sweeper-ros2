## 1. 架构

- **进程 A** `ros_sweeper_sim.py`：PhysX 刚体 + 左右差速轮（RevoluteJoint + DriveAPI）+ 前部被动万向支撑轮；订阅 `/cmd_vel` 反解轮速；发布 `/scan`（2D 射线，270° / 121 线）、`/odom`、`/tf (odom->base_link)`。
- **进程 B** `ros_avoid_controller.py`：独立外部 rclpy 进程，仅用 `/scan` 扇区距离 + `/odom` 位姿做直行/绕障/脱困决策，10 Hz 发布 `/cmd_vel`，**无硬编码航点**；**全部超时/卡死判定使用 `/odom` 头部的仿真时间戳**，不读现实墙钟（离屏循环约 0.1× 实时，墙钟超时会误判为卡死）。

## 2.1 时钟与频率说明

- **时钟纪律**：`/scan`、`/odom`、`/tf` 的 header stamp 全部写 **仿真时间**（帧号/30）；B 侧以 `/odom` 时间戳作为唯一时基，卡死判定 = 连续 3.0 s 仿真时间（90 帧）累计位移 < 0.10 m **且** `/scan` 最近距离 < 0.55 m，脱困持续 1.2 s 仿真时间。v1 的墙钟版在空旷区会误触发 `v=-0.20 m/s` 倒车。
- **频率**：离屏渲染循环即仿真时钟，1 帧 = 1 个物理步（1/30 s）= 发布一次话题；容器内 600 帧耗时约 200 s 墙钟，故话题观测频率约 3 Hz，而成片仍按 30 fps 逐帧编码，视频时间与仿真时间一一对应。
- **`/cmd_vel` 采样**：B 以 10 Hz 发布，A 每帧只取最新一条 Twist（last-value 语义 + 队列深度 10），因此 A 侧收条数少于 B 侧发条数属正常。
